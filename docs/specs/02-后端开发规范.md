# 后端开发规范 · CampusClaw · TeamVibe

适用：`backend/` 下的 Python 代码与对外接口契约
被谁读到：规则文件 `.cursor/rules/backend.mdc`，globs `backend/**/*.py`

---

## 1. 分层与依赖方向

```
backend/app/
  main.py         入口：配置加载、中间件装配、异常处理器、路由挂载
  api/v1/         HTTP 层：路由、依赖注入、入参绑定与结构校验
  services/       业务规则层：状态机、配额、归属判定、事务边界
  repositories/   持久层：唯一执行 SQL 的地方
  models/         SQLAlchemy 2.x ORM 映射
  schemas/        Pydantic v2 出入参模型
  core/           config / security / logging / errors / deps
  integrations/   llm / embedding / vectorstore / storage 客户端
backend/migrations/   Alembic 迁移
backend/tests/        unit / api
```

依赖只允许自上而下：

```
api → services → repositories → models
        ↘ integrations
core 可被任意层依赖
```

- `api/` **不得** import `repositories/`（不许绕过业务层取数）；
- `services/` **不得** import `fastapi.Request`、`fastapi.Depends`（业务层不知道 HTTP）；
- `repositories/` **不得** import `services/`；
- 除 `repositories/` 外任何文件不得出现 SQL 文本（`select(`、`text("`、原生字符串 SQL）；
- 除 `services/` 外任何文件不得直接 import `integrations/`。

**判据**：评审时问一句「这个模块依赖了谁」，答案里出现反向箭头即为违规。`make check` 的 `layout` 子项会扫 import 图并对此报错。

## 2. 接口命名与版本

- 统一前缀 `/api/v1/`；资源小写复数：`/api/v1/materials`、`/api/v1/sessions`、`/api/v1/classes`。
- 方法语义固定：列表与详情 `GET`，创建 `POST`，整体替换 `PUT`，局部更新 `PATCH`，删除 `DELETE`。
- 动作型接口用名词后缀，不用动词路径：`POST /api/v1/materials/{id}/reindex`，不写 `/api/v1/reindexMaterial`。
- 路径参数只用内部 ID（ULID 26 位），不用自然键；查询参数用 `snake_case`。
- 破坏性变更升版本前缀，不在 `/v1` 内改语义。

## 3. 统一响应结构与错误码

成功与失败走同一套外层结构，由 `core/errors.py` + 全局异常处理器统一产出，路由函数**返回业务对象**，不手写外层：

```json
{ "code": 0, "message": "ok", "data": {}, "request_id": "01HQ7Z3K9V2M4T8R6B1C0X5DNP" }
```

错误码分区，新增必须登记到 `core/errors.py` 的 `ErrorCode` 枚举与本表：

| 区间 | 含义 | HTTP | 已登记 |
| --- | --- | --- | --- |
| 0 | 成功 | 200 / 201 | `OK` |
| 1000–1099 | 参数与校验 | 400 | `1001` 参数缺失或类型错误、`1002` 超出范围、`1003` 枚举值非法、`1004` 分页参数非法、`1005` 排序字段不在白名单 |
| 1100–1199 | 未认证 | 401 | `1101` 未登录或会话过期、`1102` 会话令牌无效 |
| 1200–1299 | 未授权与跨资源 | 404 | `1201` 跨班访问（响应与 1301 完全一致）、`1202` 角色不足（学生调教师端，同为 404） |
| 1300–1399 | 资源不存在 | 404 | `1301` 资源不存在、`1302` 资料不存在或已删除 |
| 1400–1499 | 业务规则不满足 | 409 | `1401` 状态不允许该操作、`1402` 超出配额（本班资料数 > 500） |
| 1500–1599 | 依赖不可达 | 503 | `1501` 模型不可达、`1502` 向量库不可达、`1503` 对象存储不可达；`1500` 骨架期能力未实现（HTTP **501**，见 PC-15） |
| 1600–1699 | 频率限制 | 429 | `1601` 请求过于频繁 |
| 1700–1799 | 服务内部错误 | 500 | `1701` 未预期的服务端错误（堆栈只进日志，响应体只给短句） |

约定：

- `message` 是给人看的中文短句，不含内部标识、不含堆栈；堆栈只进日志。
- `data` 在失败时固定为 `null`，不放调试信息。
- 跨班一律 404：`1201` 与 `1301` 的 `message`、`data`、HTTP 状态**逐字节一致**，只有 `request_id` 不同。
- **唯一例外**：`/health`、`/health/live`、`/health/ready` 不走本信封，直接返回体检结构（字段见 `docs/specs/05-部署运维规范.md` §3）。原因是探针与负载均衡只认 HTTP 状态码与固定字段，套信封会让探针多一层解析。除这三个端点外，任何接口不得自定响应结构。

## 4. 校验位置

- **结构校验与范围校验在 `api/` 的绑定环节完成**（Pydantic `schemas/`，`Field(ge=, le=, max_length=)`）；进入 `services/` 的对象一律视为已校验。
- **业务规则校验在 `services/`**：状态机（`processing` 的资料不可检索）、配额、归属判定，返回 14xx 区间错误码。
- **归属判定（越权）在 `repositories/` 的查询条件里落地**：取单条资源的查询必须同时带 `id` 与 `class_id`，取不到即 1301——不在业务层「先查再判断」。
- 非法筛选**必须明确报错**，不得静默忽略后返回全量：`mode=foo` → 400 `1003`；`sort=password` → 400 `1005`。

**判据**：把必填校验从 `schemas/` 挪进 `services/`，评审应能发现；把 `mode` 改成非法值，接口应返回 400 而不是全量数据。

## 5. 数据访问与事务

- SQL 只出现在 `repositories/`；使用 SQLAlchemy 2.x 表达式或 ORM，禁止字符串拼接。
- 事务边界在 `services/`：一个用例一个事务，`repositories/` 不 `commit()`、不 `rollback()`。
- **事务内不得夹带外部调用**（模型、嵌入、向量库、对象存储）：先提交业务写入，再异步投递处理任务；外部调用失败留一条待处理记录，由重跑任务补偿。
- 列表查询必须显式 `limit`；`page_size` 上限 50，无上限的 `select` 视为缺陷。

**判据**：在 `services/` 里搜 `await llm` / `await qdrant`，若被包在 `async with session.begin()` 内即为违规。

## 6. 幂等与并发

- `POST /api/v1/materials` 声明为幂等：接受请求头 `Idempotency-Key`（客户端生成的 ULID），同键重复请求返回首次结果（HTTP 200，`code=0`），不新建第二条。
- `POST /api/v1/classes/join` 幂等：已是成员时返回 200 与当前成员信息，不报 409。
- 唯一约束落在存储层：`memberships(class_id, user_id)`、`chunks(material_id, chunk_index)` 建唯一索引；**不在应用层做「先查有没有再插」**。
- 并发更新用条件更新（`WHERE status = 'pending'`），受影响行数为 0 即视为状态冲突 1401。

## 7. 配置外置

- 配置只从 `core/config.py` 的 `Settings`（pydantic-settings）读环境变量获得；代码里不出现地址、密钥、阈值的字面量。
- **必填键的权威清单**（与 `specs/platform-core/spec.md` 的 PC-01/02/03 一致，任何地方出现第二份清单即为缺陷）：

| 键 | 约束 |
| --- | --- |
| `SESSION_SECRET` | 长度 ≥ 32 字节，否则视为缺失 |
| `DATABASE_URL` | 非空，含 `postgresql+asyncpg://` |
| `QDRANT_URL` | 非空，`http(s)://` |
| `LLM_BASE_URL` | 非空，host 必须在 `ALLOWED_OUTBOUND_HOSTS` 内 |
| `LLM_API_KEY` | 非空 |
| `LLM_MODEL` | 非空，含版本号 |
| `EMBEDDING_MODEL` | 非空 |
| `WEB_PORT` | 整数 1–65535 |

- **条件必填**：`SEED_TEACHER_PASSWORD` / `SEED_STUDENT_PASSWORD` 只在 `APP_ENV` 为 `dev` / `test` 时必填；`APP_ENV=prod` 时**存在即启动失败**（避免预置账号进生产）。
- 其余键（`SEARCH_*`、`UPLOAD_*`、`CHUNK_*`、`LLM_TIMEOUT_SECONDS` 等）有默认值，缺失不阻断启动。
- 必填项缺失时**启动失败**（`SystemExit(1)`），日志里打印缺失键名，不带随机值继续运行：

```
{"ts":"...","level":"error","module":"config","event":"missing_env","keys":["SESSION_SECRET"]}
```

- `SESSION_SECRET` 长度 < 32 字节视为缺失；`APP_ENV=prod` 时额外校验不得存在 `SEED_*` 值。
- 端口、阈值、模型名全部来自 `.env`，容器内不硬编码。

## 8. 分页、排序与筛选

- 分页统一 `page`（默认 1，≥1）与 `page_size`（默认 20，上限 50），响应 `data` 内带 `total`、`page`、`page_size`。
- 排序字段白名单：`created_at`、`title`；`order` 只允许 `asc` / `desc`。
- **排序必须带唯一兜底键**：`ORDER BY created_at DESC, id DESC`，避免翻页重复或漏行。
- 筛选参数全部显式枚举，未知值报 400；多个筛选条件之间是 AND，不隐式 OR。

**判据**：同一批数据按 `created_at` 翻两页，不应出现重复行；把 `page_size=1000` 传入必须返回 400 `1004`，**不得静默钳到 50 后返回数据**（静默钳位会让调用方以为拿到了全量，与 `platform-core` 的 PC-07 冲突）。

## 9. 日志与可观测

- 一行一条 JSON，由 `core/logging.py` 统一产出；字段见 `docs/specs/05-部署运维规范.md` §4。
- 每个请求一条访问日志，带 `request_id`、`route`、`status`、`latency_ms`；`request_id` 从请求头 `X-Request-ID` 继承，无则生成 ULID 并回写响应头。
- 不落日志：会话令牌原值、口令、资料正文、学生提问原文（只记长度与哈希前 8 位）。

## 10. 异步与错误处理

- 所有 I/O 用 `async`；阻塞调用（文件解析、同步 SDK）放 `run_in_threadpool`。
- 不吞异常：`except Exception: pass` 视为缺陷；捕获后要么转成登记过的错误码，要么加日志再抛。
- 外部依赖失败按 15xx 区间返回，并给出下一步提示（如「改用关键词模式」），不做无限重试。

先判是「一次性实现偏好」还是「规范缺失」：前者改代码，后者改本文件并在变更说明里记录改动理由与影响面。
