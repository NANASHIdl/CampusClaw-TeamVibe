# 测试规范 · CampusClaw · TeamVibe

适用：`backend/tests/**`、`frontend/src/**/*.spec.ts`、`e2e/**`
被谁读到：规则文件 `.cursor/rules/testing.mdc`，globs `backend/tests/**/*.py`、`frontend/src/**/*.spec.ts`；技能 `skills/write-tests/SKILL.md`

---

## 1. 层次与位置

| 层次 | 放哪里 | 覆盖什么 |
| --- | --- | --- |
| 单元 | `backend/tests/unit/<模块>/test_*.py` | 业务规则：切片规则、阈值判定、状态机、配额、引用编号生成 |
| 接口 | `backend/tests/api/<URL 路径>/test_<方法>.py` | 每条能力的正常路径与失败路径，断言状态码 + `code` + 关键字段值 |
| 前端组件 | `frontend/src/**/__tests__/*.spec.ts`（Vitest） | 视图四状态与检索无命中形态、表单校验时机、术语表文案 |
| 端到端 | `e2e/<场景>.spec.ts`（Playwright） | 只覆盖主路径：登录 → 检索 → 提问 → 看到出处 |

接口测试目录与 URL 对齐，文件名就是方法：

```
backend/tests/api/api/v1/materials/test_get.py       # GET  /api/v1/materials
backend/tests/api/api/v1/materials/test_post.py      # POST /api/v1/materials
backend/tests/api/health/test_get.py                 # GET  /health
```

## 2. 用例来源：每个测试说得出在判哪一条规约

测试函数名或 docstring 里写清规约编号（`<能力前缀>-<序号>`，与 spec 的 Scenario 编号一致）：

```python
async def test_materials_cross_class_returns_same_404():
    """MT-08 跨班与不存在返回一致的 404（依据 docs/specs/03 §2）"""

async def test_search_unknown_mode_returns_1003():
    """RT-06 mode 非法值报参数错误（依据 docs/specs/02 §4）"""
```

说不出在判哪一条的测试，通常是顺手写的形状检查，删掉比留着好。

## 3. 三类组织（含边界）

每条能力按正常路径 / 失败路径 / 边界归组：

- **正常路径**：教师上传 PDF → 状态 `ready` → 学生检索命中并返回出处。
- **失败路径**：跨班访问、未登录、角色不足、参数非法、资源不存在、依赖不可达（Qdrant 停掉时 `mode=hybrid` 返回 503 `1502`）。
- **边界**：空资料库；`SEARCH_VECTOR_MIN=0.35` 上下各取一个分数（0.34 / 0.36）；`page_size` 取 1 与 50；上传恰好 20 MiB（通过）与 20 MiB + 1 字节（拒绝）；提问恰好 2 字符与 500 字符。

边界用等价类划分的两端，不用随机值。**随机化只能用来造数据，不能用来定断言。**

## 4. 不许只断言形状

这三句放在一起，把被测逻辑改坏它还是绿的：

```python
assert resp.status_code == 200
assert data is not None
assert len(data["items"]) == len(seeded)
```

要断言值：

- 跨班访问的响应体与「不存在」的响应体，除 `request_id` 外逐字节相同；
- 混合检索的结果里不含 B 班任何资料的 `title`；
- 无命中时 `data["answer"]` 等于固定文案「资料中未找到相关内容」，且 `data["citations"] == []`；
- 幂等键重复提交后，`materials` 表行数不增加（查库断言，不只看返回体）。

**判据：把被测逻辑改坏，这个测试会不会红。** 会红才算断言到了行为。

## 5. 数据隔离

- 测试用独立库：`docker compose -f docker-compose.test.yml` 起一套 PostgreSQL + Qdrant，库名 `campusclaw_test`；**禁止连开发库**。
- 预置 A / B 两班（各 1 名教师、2 名学生），口令取自 `.env` 的 `SEED_*_PASSWORD`。
- 每条用例在自己的事务里执行并回滚（fixture `db_session`）；不依赖执行先后，随机顺序（`-p no:randomly` 关闭随机化后结果一致）。
- 端到端用例执行前重建种子数据（`make seed-test`），执行后清理。

## 6. 外部依赖用替身

- 模型与嵌入在单元 / 接口测试中用替身（`tests/fakes/llm.py` 返回固定文本与固定向量）；只有 `e2e` 打真实服务，且只在只读数据上执行。
- 禁止依赖真实时间（用 `freezegun` 或注入 `Clock`）与真实外网：**断网后单元与接口测试应全部通过**。
- 依赖不可达场景用「指向不存在的端口」制造，不用 monkeypatch 抛异常（要验证的是超时与降级路径，不是异常类型）。

## 7. 一键运行与通过判定

```bash
make check        # 全量门禁
make test-api     # pytest -q backend/tests
make test-web     # vitest run
make e2e          # playwright test
```

- 任一子项非零退出码即未通过，**不得为了让门禁变绿而放宽其中的检查或删断言**。
- `pytest.skip` / `it.skip` 必须带理由与追踪编号；跳过用例数只许下降，不许增长。
- 覆盖率只作参考指标，不设百分比门槛；**替代它的是「每条 Scenario 至少一条用例」**，缺口由 `docs/lesson-07/02-capability-scenario-matrix.md` 暴露。

## 8. 缺陷判定口径

先定**用哪套信号**，再判属于哪一类。本项目固定四路信号，缺一路不算判定完成：

| 信号 | 看什么 |
| --- | --- |
| HTTP 状态码 | 是否落在规约声明的状态 |
| 响应体 `code` | 是否落在登记过的错误码区间 |
| 关键字段值 | `citations`、`hits`、`status`、`total` 的具体值 |
| 日志字段 | `request_id`、`event`、`error_code`、`latency_ms` 是否成链 |

四类缺陷，按「用户看到什么」定义：

| 类型 | 定义 | 典型例子 |
| --- | --- | --- |
| **被当成成功** | 本该失败的操作返回 `code=0` | 跨班删除返回 200；无命中却给出编造出处 |
| **被放行** | 本该拒绝的访问通过了 | 学生调到教师端接口；B 班会话读到 A 班资料 |
| **被误拒** | 合法操作被拒绝 | 本班教师上传合法 PDF 被 1402 拦；合法 `mode=hybrid` 报 1003 |
| **未处理故障** | 依赖故障未转成登记错误码 | Qdrant 挂掉时返回 500 裸堆栈而非 503 `1502` |

判定顺序：**先复现 → 用四路信号定性 → 归类到上表 → 补一条能复现该缺陷的用例 → 再改代码 → 保留该用例**。

## 9. 变更时的要求

- 每次变更至少补写与其 Scenario 对应的用例；缺用例的变更不进评审。
- 修复缺陷先补用例（红），再改代码（绿），最后保留。
- 涉及安全（跨班、角色）的用例不允许被删除，只能新增。

## 违反时

失败即阻断。若认为某条断言本身写错了，改断言并在变更说明里写明原因，不由执行者自行跳过。
