# 技能：按规范做一次数据变更

## 何时用

- 新增表或字段、改枚举取值、加索引；
- 需要回填历史数据；
- 要删除字段或表。

## 步骤

1. **先定影响面**：这张表在哪些 `repositories/`、哪些接口、哪个页面被读到；把清单写进变更说明。
2. **写迁移**：`alembic revision -m "<短横小写英文名>"`，文件落在 `backend/migrations/versions/YYYYMMDDHHMM_<name>.py`。
   - 语句条件化可重跑（`IF NOT EXISTS` 语义）；
   - `downgrade()` 必须实现，文件头注释写回滚动作一句话；
   - **已合并的迁移文件不得修改**，只新增。
3. **选对顺序**：加字段 → 双写 → 切读 → 删旧字段。删字段的迁移必须晚于「切读」那次发布，且旧版本代码在新结构上仍可运行。
4. **同步数据字典**：`docs/data-dictionary.md` 加/改对应条目（用途、类型、约束、含义、敏感级）。`make check` 的 `docs-lint` 会校验，漏了会红。
5. **敏感分级**：新字段属于哪一级？机密字段不得出现在任何响应体与日志中；提问原文不进 `ask_logs`（只存长度与 SHA256 前 8 位）。
6. **验证往返**：`alembic upgrade head` → `alembic downgrade -1` → `alembic upgrade head` → `alembic check`（应无差异）。
7. **涉及删除时核对副本清单**：业务库 → 向量库 → 对象存储 → 缓存 → 备份（备份在下一次轮转后消失，**写进删除记录，不假装立即消失**）。
8. **补测试**：迁移相关至少一条用例（结构或约束生效），删除类至少一条「删完查不到」的用例。

## 完成判据

- `alembic downgrade -1` 可执行，往返后 `alembic check` 无差异；
- 数据字典已同步，`make check` 的 `docs-lint` 与 `layout` 绿；
- 变更说明里有「回滚动作」一行；
- 删除类变更的记录里写明五个副本各自的处理结果。
