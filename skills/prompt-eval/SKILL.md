# 技能：改一次提示词并跑评测

## 何时用

- 要改 `backend/app/prompts/` 下的模板；
- 要换模型名 / 版本 / 温度 / 阈值；
- 评测通过率下降，需要定位是模板问题还是检索问题。

## 步骤

1. **先看基线**：打开最近一份 `docs/eval/*.md`，确认当前通过率与失败条目。
2. **复制新版本**：`cp prompts/answer_v1.md prompts/answer_v2.md`，**不改旧文件**（历史要能追溯）。
3. **改文件头四行**：

   ```
   <!-- prompt: answer | version: 2 | updated: 2026-11-04 -->
   <!-- eval: docs/eval/2026-11-04-answer-v2.md | pass: PENDING -->
   <!-- owner: TeamVibe -->
   ```
4. **只改一处**：一次只改一个维度（引用格式 / 拒答措辞 / 上下文使用方式），否则失败时说不清是哪处导致的。
5. **跑评测**：`make eval`。20 条必须全过：必答 10（含可核对出处）+ 必拒 10（跨班 3、无依据 4、诱导 3）。
6. **归档**：写 `docs/eval/YYYY-MM-DD-answer-v2.md`：版本、模型名、阈值、逐条结果、失败原因、结论（采用 / 回退）。
7. **回填**：把文件头的 `pass: PENDING` 改成实际通过数。
8. **提交**：走 `spec-change` 的变更流程，变更说明里贴评测结论。

## 完成判据

- `make eval` 退出码 0，通过 20/20；
- 新模板文件头 `eval:` 行指向存在的归档文件，`pass:` 为实际值；
- 旧模板文件未被修改（`git diff` 只显示新增文件）；
- 日志中 `prompt_version` 与 `messages.prompt_version` 为新版本号。

## 不允许

- 为了让结果变好而删题、改题面或放宽 `must_cite`；
- 跳过评测直接合并；
- 把模板挪进 `.env`（它不是配置项）。
