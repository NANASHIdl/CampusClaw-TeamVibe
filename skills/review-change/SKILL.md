# 技能：按规范评审一次变更

## 何时用

- 有人请求你评审（一个工作日内响应）；
- 自己要合并前做最后一遍自审。

## 步骤

1. **看规模**：diff 是否 ≤ 600 行（不含锁文件与迁移）、是否只动了 `tasks.md` 里的一组任务。超了直接退回拆分，不再往下看。
2. **逐条对 Scenario**：打开 `specs/<能力>/spec.md`，对每条 Scenario 问一句「这条真的满足了吗」，看代码或跑用例，不看作者描述。
3. **授权判定**：互换两个班的 ID 重放请求，响应除 `request_id` 外应逐字节相同；学生调教师端接口应是 404 而不是 403。
4. **迁移**：`alembic downgrade -1` 能否执行；是否先加后删；数据字典是否同步。
5. **提示词**：模板版本号是否 +1，`docs/eval/` 是否有对应记录且 20/20。
6. **门禁**：`make check` 14 项是否全绿；有没有 `--no-verify`、放宽检查、删断言的痕迹（`git log -p -- Makefile .githooks/ AGENTS.md`）。
7. **证据三字段**：`Change` 指向的变更目录存在、`Verify` 的命令跑得出、`Evidence` 的文件存在。
8. **例外**：是否书面化（理由 + 失效条件 + 复核日期）。口头豁免一律不认。
9. **写结论**：通过 / 打回，打回必须写「哪条规约、哪条 Scenario、怎么复现」。

## 检查表（照着打勾）

| 项 | 判据 |
| --- | --- |
| 规约覆盖 | 每条 Scenario 都有对应用例，且用例改坏逻辑会红 |
| 授权 | 跨班 404 一致；角色不足 404；`class_id` 只取自会话 |
| 数据 | 迁移可回滚；字典已同步；删除副本清单已核对 |
| 提示词 | 版本 +1；评测 20/20 并归档 |
| 门禁 | 14 项全绿，无放宽痕迹 |
| 证据 | 三字段值都查得到 |
| 规模 | ≤ 600 行、只动一组 |

## 完成判据

评审结论已写进变更说明（谁审、审了什么、结论、打回原因）；合并后 `main` 上的 `make check` 仍绿。
